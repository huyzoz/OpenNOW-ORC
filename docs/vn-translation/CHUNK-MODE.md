# Chunk mode (v4) — pre-translated WuWa database

Status: design + implementation in progress (2026-11-12). Translation
batch (55 chunks, WuWa 3.8) runs separately in
`~/workspace/wuwa-vi-translation/`; this doc covers the client side only.

## Idea (Ethan's spec, 2026-11-12)

Translate the whole game text ONCE, offline, into a chunk database.
At runtime the client looks a line up in the database instead of calling
an AI model: no tokens, no translate latency. AI providers (v3 custom API
etc.) stay as the fallback for lines the database does not have.

## Data — chunk repo (separate repo, NOT inside the app)

Repo: `huyzoz/wuwa-vi-chunks` (public; created 2026-11-12 13:05 on huyzoz
— the account with the working browser session and CI; the data repo
needs no Actions).
Layout:

- `manifest.json` — one object:
  `{"game":"Wuthering Waves","version":"3.8","title":"Lilies in a Dying Dream","chunks":55,"uniqueStrings":216384,"words":3133145,"updated":"2026-11-12","files":["chunks/vi_chunk_001.json", ...]}`
- `chunks/vi_chunk_NNN.json` — one file per translation chunk, same shape
  as the translation cache so `WuWaDialogueDb::loadDialogueDb` reads it
  unchanged: `{"version":1,"entries":{"<english line>":"<vietnamese line>", ...}}`
  (keys are the raw English strings; the loader normalizes them).
  Generated by `gen_client_chunks.py` in `~/workspace/wuwa-vi-translation/`
  from the merged `vi_multi_38.json` (55 files, ~43 MB total, largest
  1.9 MB — each browser-uploadable). `vi_chunk_043.json` currently holds
  only the 1,000 finished items of chunk 043 (finisher running); a re-run
  of the generator overwrites the same filename with the full 4,000.
- `README.md` — what the data is, where it came from (Arikatsu
  `WutheringWaves_Data` branch 3.8 textmap, translated by Muse), version.

Why chunks instead of one big file: each file is ~1 MB (browser-uploadable,
resumable, cache-friendly). The client downloads the manifest first, then
only the chunk files it does not already have cached for that version.

## Client — download + cache

- Cache dir: `QStandardPaths::CacheLocation + "/wuwa-chunks/<version>/"`.
- `WuWaDialogueDb` gains: `loadChunkFile(path)` (merge entries WITHOUT
  clearing, so 55 files accumulate into one map) and `lookupFuzzy(text,
  translated)` (normalized exact first; then candidates sharing the first
  word, Levenshtein ratio >= 0.88 — OCR text is never byte-perfect).
- Download runs on the translation worker thread via
  `TranslationHttp::request("GET", url)` (raw.githubusercontent.com).
  Progress + errors surface through engine status, never as a modal.
- The DB loads lazily: only when chunk mode is enabled AND a game is
  selected. Chunk mode OFF = zero network, zero memory, zero behavior
  change (v3 path untouched).

## Lookup order (live job, in TranslationWorker::processNext)

After OCR returns blocks, BEFORE any provider call, per block:
1. Chunk DB exact lookup (normalized key).
2. Chunk DB fuzzy lookup.
3. Memory cache (`TranslationCache`).
4. Configured provider (Google / Gemini / custom) — only for misses.
   A miss result is inserted into the memory cache as usual, so the
   provider is called at most once per unseen line.

A block that hits the DB reports `translateMs = 0` and the timing pill
shows "Chunk hit". The TEST section (`requestTestTranslation`) consults
the DB first too.

## Coordinate memory

`TranslationEngine` keeps `stableRects: normalizedOriginal -> {rect,
hits}`. When a completed job's block rect matches the stored rect for
the same text within tolerance, hits++. At hits >= 2 the rect is
"stable": the next `emitTranslation` snaps a jittering OCR rect to the
stored one, so boxes stop shaking. This only affects overlay placement,
never the stream.

## Overlay — white inlay (khảm trắng), BLACK IS BANNED

`TranslationBox` in `TranslationOverlay.qml`:
- Background: white frosted glass — semi-transparent white
  (`Qt.rgba(1,1,1,0.82)`) over a live blur of the video behind it
  (QtQuick.Effects `MultiEffect` on a `ShaderEffectSource` of the stream
  item, clipped to the box). If the blur effect is unavailable it
  degrades to plain translucent white — never black, never opaque.
- Text: dark (`#1a1a2e`), `Be Vietnam Pro`, neat sizes (same
  `fontSizePx` control).

## Font — Be Vietnam Pro

- Source: google/fonts `ofl/bevietnampro` (SIL OFL 1.1 — free to bundle).
- Weights bundled: Regular, Medium, SemiBold, Bold (~545 KB total).
- Verified 2026-11-12 with fontTools: all four cover every tested
  Vietnamese codepoint (ơ Ơ ư Ư đ Đ + tone vowels) — zero missing glyphs.
- Loaded at startup via `QFontDatabase::addApplicationFont(":/fonts/...")`
  (Resources.cmake `opennow-translation-fonts`, PREFIX `/fonts`).
  Overlay uses `font.family: "Be Vietnam Pro"`; everything else keeps
  `Theme.bodyFont` (Nunito).

## Settings UI — "Dịch Chunk" section

New panel in `DesktopSettingsTranslationPage.qml` (after CUSTOM API,
before DISPLAY):
- Toggle "Dịch Chunk" (`translationEngine.chunkEnabled`, QSettings
  `translation/chunkEnabled`, default OFF).
- Game picker (`DesktopSettingsChoice`, `chunkGame`): currently only
  "Wuthering Waves". Built as a list so future games slot in.
- Detail card (visible when a game is selected): game title, chunk
  version, words translated ("3.133.145 từ · 216.384 câu"), chunk count,
  download status/progress, "Tải chunk" button, GitHub link (text link
  → `Qt.openUrlExternally`, repo URL from the manifest).
- All new copy goes through `locales/en.json` (`translation.qmlSource`).

## Hard constraints

- NOTHING in this change touches the stream: no edits to
  `native/opennow-streamer/`, `native/opennow-core/`, FFI ABI, or the
  video item. Translation stays a QML overlay + worker thread.
- Chunk mode OFF = v3 behavior exactly (same code paths, same settings).
- No API key is needed for chunk mode itself (OCR still needs whatever
  engine the user chose; the DB lookup itself is free and local).
- `publish_nightly` stays false; CI runs on huyzoz `gh-runners`.
